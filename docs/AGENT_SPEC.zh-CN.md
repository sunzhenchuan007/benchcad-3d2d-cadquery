# BenchCAD 3D2D CadQuery：API Agent 的运行规则

这套程序让模型读取 STEP，写 Python 生成 DXF，再让另一个独立的模型任务依据
DXF 重建 STEP。控制程序负责执行、返回反馈、限制预算和保存结果。

## 1. 输入：谁能看到什么

出图模型收到任务说明和工具说明，可用 Python 读取 `input/model.step`。
它可以计算几何数据，也可以生成图纸预览；不会收到专家图纸或评分答案。

重建模型只收到最终 `input/drawing.dxf`、相应 PNG 和通用说明。
首条消息直接附带这张 PNG。它拥有全新的上下文和工作目录，看不到原始 STEP、
出图代码、出图日志或工作状态 JSON。评分程序单独持有原始 STEP。

## 2. 工具：模型具体能做什么

模型可使用 Python、CadQuery/OCP、ezdxf、PyMuPDF、Pillow、NumPy/SciPy。
提供的辅助函数可生成主视投影、真实全剖、线性尺寸和 PNG；也可直接使用底层库。
半剖、阶梯剖尚无专用辅助函数，需要模型通过真实几何运算构造。

模型决定视图、剖切位置、比例、排版和标注。工具不会替模型选择专家答案。
准确的参数、坐标规则和例子见 [工具说明](../benchcad_cadquery/TOOLS.md)。

## 3. 交互：30 轮怎样计算

控制程序调用一次 API，模型返回一个决策响应，就计一轮。
每个响应只能包含一个 `python` 或 `submit` 代码块；代码块里可以有多条 Python 语句。
格式错误、代码报错、拒绝响应、未完整生成的响应和最终提交都计入 30 轮。
网络失败没有收到可用决策时，另计请求失败；每阶段累计最多允许 3 次。

普通 `python` 执行完，模型得到退出码、有限长度的标准输出和错误信息。
模型在工作目录顶层或 `output/` 直接一层保存的新增或改变的 PNG，会验证并复制到模型无法改写的位置，
作为下一轮图片反馈；其他子目录不自动扫描。反馈明确列出本次附带图片数；被拒绝的图片另有错误说明。
图片以实际图像内容发送给模型，不仅是文件路径；同名图片修改后会重新发送，历史快照保持不变。
一次 API 请求最多 64 MiB（含重复历史和图片编码）；超限明确记录框架请求预算失败，不静默删历史。
图片编码、文本计数和请求序列化也计入阶段时间。请求体积限制不等于控制程序的内存硬配额。
每次执行使用新容器，Python 变量消失，同一阶段的文件保留。

## 4. 输出：怎样才算提交

出图必须保存 `output/drawing.dxf`；重建必须保存 `output/model.step`。
模型最后返回 `submit` 代码块。控制程序执行这段代码，然后检查并冻结文件。
聊天里写“完成了”、仅生成文件、达到时间或轮数上限，都不等于有效提交。

DXF 要通过基本格式和非空几何检查，并由程序生成最终 PNG。
STEP 要包含有效且体积为正的实体。检查通过只说明文件可处理，不说明图纸或几何正确。
提交失败便结束该阶段，不再提供提交后的修复机会。辅助工具产生的状态 JSON 不作为可信证据。

## 5. 资源：哪些是程序真正限制的

每阶段最多 30 轮、1800 秒；一次代码执行最多 300 秒，并受剩余阶段时间限制。
每个 CAD 容器限制 1 CPU 的计算配额、4096 MiB 内存，无额外 swap，最多 128 个进程。
1 CPU 是配额，不是固定绑定某一个物理核。

容器没有网络，系统和工具源码只读，仅当前工作目录可持续写入。
API Key 留在可信控制程序中，不传入容器。专家答案、主机用户目录和 Docker 控制接口不挂载。
临时目录和日志另有限额；持久工作目录目前没有强制磁盘配额。
超时后程序删除本次容器，清理可能额外花少量时间；服务器故障仍需运维处理。

## 6. 记录：如何复查一次试验

保存模型回复、实际执行代码、执行反馈、图片快照、每阶段决策轮数、执行次数、请求尝试数、
耗时和提交文件哈希。网络失败与模型格式/代码错误分开记录。
这些原始记录只保留在私有运行目录，不整包上传 GitHub。

本地文本 token 对每次请求重新计算实际发送的文本，包含重复发送的历史。
使用固定版本 `tiktoken/o200k_base`，但它不是已经验证过的目标模型 tokenizer。
图片、隐藏推理、缓存及完整账单 token 无法由本地文本计数器得知，不能当作零。
中转站 usage 只作诊断；没有已核实的价格时费用保持空值。

## 7. 评分：现在做什么、暂停什么

独立重建结束后，评分程序比较原始 STEP 和重建 STEP。
两者分别居中并统一缩放，再在 24 个正旋转和 24 个镜像方向中取最高体素 IoU。
另外记录尺寸比例，避免把归一化 IoU 误认为绝对尺寸准确率。
同时保留原始 IoU 和基本体基准 b（长方体、球、圆柱中最高的 IoU）。
校正值 q = clamp((IoU-b)/(1-b), 0, 1)；b=1 时仅原始 IoU=1 才给 q=1，否则 q=0。
重建得分使用 q：q≤0.90 为 0 分，q≥0.99 为 100 分，中间线性映射。
这是重建分，不是工程图总分；基本体校正不需要专家图纸重建。

剖切匹配、标注碰撞只保留接口，分数为空；专家 DXF 重建后的基线修正暂停。
不把尚未实现的指标填成满分，不生成虚构总分。
具体算法与限制见 [评分说明](../evaluation/README.md)。

## 8. 部署与验收：在哪里运行

Windows 上使用本地 Codex 开发和检查代码；Linux 服务器运行自定义 API 控制程序与 Docker。
被测 Agent 是本仓库的 API 循环，不是 Codex CLI。无需在 Windows 安装 WSL 或 Docker。

新部署依次检查：依赖能加载、固定样例能出图及提交、文件权限与资源限制生效、
同一 STEP 对比自身的 IoU 为 1，最后才运行付费模型。
固定样例成功只证明流程可运行；复杂图纸质量与实际模型成绩必须另看试验报告。
